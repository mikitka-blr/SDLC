# Выбор JavaFX с FXML для пользовательского интерфейса

## Контекст и постановка задачи
SRS фиксирует desktop-приложение на Java 17 и JavaFX (`REQ-CON-002`). Интерфейс состоит из четырёх экранов с повторяющимися элементами: шапка, подвал, прогресс-бары, кнопки оценки (`REQ-CON-013`). Нужно выбрать способ построения интерфейса.

## Драйверы решения
* Повторное использование компонентов интерфейса (`REQ-CON-013`).
* Соответствие структурным диаграммам SysML v2 (`REQ-UI-006`).
* Разделение разметки и логики для параллельной работы Senior и Junior.

## Рассмотренные варианты
* **Вариант 1:** JavaFX + FXML
* **Вариант 2:** JavaFX, интерфейс целиком в коде
* **Вариант 3:** Swing

## Итог решения
Выбран вариант **«JavaFX + FXML»**, так как разметка отделена от контроллеров, а шапка, подвал и прогресс-бар оформляются отдельными FXML-компонентами.

### Последствия
* **Хорошо**, потому что разметка экранов легко сопоставляется с диаграммами SysML v2.
* **Хорошо**, потому что Junior может править разметку, не затрагивая бизнес-логику.
* **Плохо**, потому что ошибки в FXML (имена полей, обработчики) обнаруживаются только при запуске.

### Подтверждение
Код-ревью: контроллеры не содержат SQL и бизнес-правил; ручная проверка переходов между экранами по таблице из SDD (`005-interface`).

## Плюсы и минусы вариантов

### JavaFX + FXML
* Хорошо, потому что соответствует `REQ-CON-002` и `REQ-CON-013`.
* Плохо, потому что нужно изучить связывание FXML и контроллеров.

### JavaFX без FXML
* Хорошо, потому что проверка типов на этапе компиляции.
* Плохо, потому что разметка смешивается с логикой, повторное использование сложнее.

### Swing
* Хорошо, потому что входит в JDK.
* Плохо, потому что противоречит `REQ-CON-002` и устарел визуально.

## Дополнительная информация
* Связанные требования SRS: `REQ-CON-002`, `REQ-CON-013`, `REQ-UI-001`…`REQ-UI-006`.
* Связанные элементы SDD: `002-composition`, `003-structure`, `005-interface`.
